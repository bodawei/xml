ISSUES
--------
* ISSUE: Need to figure out what to do with xml decl not being an xml decl
The stuff below ultimately requires more "look ahead" than we do at the moment. the main problem is if we say "skip junk until xmldecl found", what happens if we find <?xml junkjunkjunk?> ? That, then, is still junk.  We could indeed detect that when getXmlDecl reports tons of errors.  in which case we could continue with "junkjunkjunk" in some way  But then we need to put the token(s) back into the string cursor, briefly. Either that, or we consider that something we can't cope with.
And if we want to allow a non-xmldeclaration document, and want to skip over junk, do we go to the first <name?
And, what if the xmldecl is found after the start of markup?  do we want to be able to start reading an <?xml and then find it is something else and turn it into an ordinary processing instruction in some way?
***Maybe that's the solution to the above. The skip junk looks for <[^ ] pair of characters via peek. if it finds that, and it is <name or <? or <! then we go ahead and do what we should.  We also modify the getXmlDecl to decide it is having just too many problems and turn itself into a processing instruction.  And still maybe the skipping should go until we actually find an xml declaration.***
